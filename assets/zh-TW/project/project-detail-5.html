專案介紹

擺脫過時老舊的設計與繁瑣的架構層級，全新界面不僅現代美觀，還針對使用體驗進行全面優化，重新梳理導航結構，讓客戶能輕鬆維護前台資料，輕鬆找到所需功能，避免迷路。

我的角色和交付成果

執行專案時我身兼數職，工作內容涵蓋各個方面，包括前期研究、介面設計、流程優化和元件互動等。透過持續優化流程與強化元件互動，致力提升使用者體驗的品質。我對公司執行過的專案進行類別歸納與功能整合，並最大化後台模組的設計效能。同時，梳理後台架構並進行競品系統介面的深入分析，確保設計決策基於對市場的深度理解與全面評估，為產品未來的發展願景提供清晰的規劃與支持。

專案執行困難點

  • 專案類型多且架構複雜程度落差很大

    整合公司所有專案功能時，面臨類型多樣且複雜程度不一的挑戰。由於缺乏固定架構，版面規劃需充分考量在功能數量多時保持整潔有序，數量少時則避免畫面過於空洞，確保設計能兼顧彈性與視覺平衡。

  • 時程限制

    由於受限於開發時程及人員重新學習的時間成本，我們需在不改動架構的前提下對版面進行優化。因範圍限制較大，需要嘗試多種方向，以規劃出最適合的操作邏輯，確保提升使用體驗的同時達成專案目標。

  • 需支援手機裝置，輕鬆完成物件的刊登與上下架功能。

    這次後台改版的一大亮點在於優化手機端的使用體驗。舊版後台雖支援手機版，但介面不友善且畫面凌亂，操作起來相當不便。本次改版目標專注於提供簡單易用的刊登與上下架功能，讓用戶在手機上也能輕鬆操作。而針對更複雜的上傳功能或編輯器，則仍建議以電腦版為主要使用裝置，以確保最佳使用體驗。

前期資料統整

為提升專案價值，我們全面歸納歷年專案資料，系統性整理功能與細目，清晰呈現每個專案的核心亮點與應用場景。同時，透過內部人員深度訪談，洞察真實使用情境中的痛點與挑戰，為功能優化提供可靠依據。

分析痛點

根據訪談結果，我們精準擬定後續修正方向，包括簡化流程、優化功能結構，以及強化用戶體驗，確保解決方案的針對性與可行性。

經過訪談及自身使用經驗，整理以下主要痛點：

頁面層級過多，導致切換時容易迷失方向，且查找資料耗時。

手機版操作體驗不佳，基礎的上下架功能使用不便。

麵包屑位置不明確，且其樣式與標題過於相似，容易造成視覺混淆，影響導航效率。

當選擇類別按鈕數量過多時，版面顯得擁擠雜亂，影響介面的美觀性與用戶體驗。

當其他功能數量較多時，列表按鈕雜亂且缺乏明確區分，顯示資訊不夠清晰，易造成使用混亂。

固定單元與客製化單元混雜擺放，缺乏清晰的屬性區分，影響整體結構的邏輯性與開發效率。

部分固定單元未納入固定功能規劃，導致程式開發時常發生遺漏。

語系切換後自動導回主頁面，影響用戶的上稿連續性與操作效率。

確立整體主要改版需求

  • 簡化層級結構

    簡化層級結構、提升導航清晰度，幫助用戶快速定位所需內容，提高操作效率。

  • 優化手機端介面設計

    增強按鈕易用性與響應速度，確保功能操作更加流暢便捷。

  • 調整列表按鈕位置

    建議優化按鈕設計，增加層級或標識，提升辨識度，幫助用戶快速定位所需功能。

  • 優化類別按鈕操作形式

    客製化下拉樣式搭配簡潔的視覺樣式，減少信息密度。

  • 單元屬性歸類與整理

    將固定單元統一歸類至固定功能區，並明確區隔其與客製化單元的位置與屬性，優化規劃結構以降低開發錯誤並提升專案管理效率。

  • 調整麵包屑樣式與位置

    調整麵包屑的樣式設計，增強層級區分，並在布局上突出其位置，以提升用戶的辨識度與操作體驗感。

  • 改變後台語系資料庫架構

    調整語系切換邏輯架構，讓用戶在切換語系時能保持在原操作頁面，提升使用體驗與工作效率。

  • 圖片上傳欄位資訊顯示不清楚，操作邏輯不友善。

    上傳圖片後無法即時預覽，導致使用者無法確認當前圖片與尺寸。此外，建議尺寸的顯示位置不夠直覺，許多客戶反映難以找到相關資訊。

北極星指標：簡化層級結構，減少用戶在操作過程中迷失方向的風險。優化手機介面的操作體驗，確保功能跨裝置使用流暢，讓用戶無論在哪種設備上都能輕鬆完成操作。

線稿流程

確認需求後採用線稿方式設計三版流程方案，直觀呈現每個方案的操作邏輯與結構優劣，並進行內部團隊討論與實際需求分析，逐一評估每個流程的適配性與潛在問題，確保決策過程透明且高效。

依照架構時間成本，討論修正總結如下：

可立即執行的項目：

  • 優化手機端介面設計

  • 調整列表按鈕位置

  • 調整麵包屑樣式與位置

  • 單元屬性歸類與整理

  • 優化類別按鈕操作形式

需調整執行方向的項目：

  • 簡化層級結構 → 經與程式討論確認，層級結構為網站架構的既定規則，無法進行刪除或減少。為解決此限制，建議在保留層級規則的前提下，移除編輯頁面的滿版形式，改以左右分欄的設計呈現，實現編輯與資訊檢視同步進行的效果，提升操作效率與用戶體驗。

  • 改變後台語系資料庫架構 → 經專案討論確認，目前的架構設計是基於客戶資料在不同語系間無法完全對應的考量，因此採用分開的資料表形式，由於資料表分開的結構限制，無法實現語系直接切換功能，而若改為整合資料表，則會強制要求客戶在每個語系中提供對應內容，這與公司主要客群的需求不符。最終決定取消此項目調整，維持現有的資料表分開設計，以保障客戶的使用靈活性與需求匹配。

亮點設計呈現

在方案比較中，我們聚焦於功能完整性、用戶體驗與實施成本，最終選擇出最優解，並進一步優化細節以實現高效落地。

元件庫

包容性設計：亮暗模式切換

為滿足不同使用環境與個人偏好的需求，系統導入亮暗模式切換，研究分析其他網站的設定，比較兩種模式之間的顏色差異，進而思考如何進行配色，確保日夜間模式符合 WCAG AA 標準，提供更佳的可讀性與無障礙體驗。

分析結論：大部分的網站亮暗對比的顏色符合 WCAG AA 對比標準，通常不會進行調整，僅在顏色對比不足時才會進行適當調整以提升可讀性。

執行中的挑戰

01

專案時間分配

團隊成員在執行後台改版的同時，還需負責其他專案開發，且各自的執行時間不一定重疊。透過日曆記錄問題與交接進度，確保資訊同步。每月專案會規劃進度，合理分配各專案時程，以確保整體進度順利推進。

02

程式開發過程與挑戰

問題一：登入資安流程不健全，無防護機制。

登入時補雙重驗證機制，提升防護層級。

問題二：為了避免切頁，我們選擇右側推欄方案，但因程式碼須集中在同一檔案，當列表物件過多時，資料量將過於龐大。

程式檔採用引入方式拆分頁面，但導致關閉與返回列表按鈕位於子層，無法控制選單與父層列表的關係。
最終決議將按鈕移至外側，並移除底部返回列表按鈕。

03

易用性測試與定案解方

團隊成員在執行後台改版的同時，還需負責其他專案開發，且各自的執行時間不一定重疊。透過日曆記錄問題與交接進度，確保資訊同步。每月專案會規劃進度，合理分配各專案時程，以確保整體進度順利推進。

問題一：細目編輯物件釘選問題

原先考量上方釘選名稱與切換按鈕，以及下方釘選送出按鈕，以提升用戶操作便利性。測試後發現小螢幕的可視範圍過小，需在兩者之間進行取捨。

內部投票決議可視範圍的重要性大過上方物件釘選，故選擇移除上方釘選效果，增加可視範圍。

問題二：預覽圖片寬高尺寸比例呈現

預覽圖片原本設計為滿版顯示，但當寬高比例不符合時，使用填滿方式可能導致超出範圍的部分被裁切。若比例差異過大，則可能出現裁切過多的問題，影響圖片呈現效果。

採用等比例縮放方式，使圖片符合方框尺寸，以其中一邊貼滿，並在左右或上下留白，確保圖片居中顯示。

學習與反思

公司承接的專案多樣且複雜，規劃架構時需要考量各種不同狀況的問題，物件的擺放也須思考數量多寡對版面的差異性，最困難的是統計公司歷年專案的過程，因數量太多規則也無法統一，需要反覆審核確保後台模組的設計能夠滿足不同專案的需求。

在開發過程中，我們首先盤點了公司過往專案的特性，歸納出共用與客製化需求的比例，並依據這些數據來規劃模組的架構。我們希望透過模組化的方式，提升開發效率，減少重複性工作，讓團隊能更專注於專案的核心功能開發，這不僅能減少開發時間，也能降低後續維護成本，為了讓後台模組具有更高的靈活性，開發時特別關注模組的擴展性與兼容性。

其中也遇到了不少困難，除了面臨技術上的限制，還需要在現有開發環境內尋找最佳解決方案。由於操作方式必須配合程式技術做相應調整，我們在流程規劃階段進行了多次內部討論，不斷優化畫面與操作邏輯，最終才確立最適合的解法。

實際開發後，我們才真正理解舊系統中一些看似多餘的設計，其實是為了解決特定問題而存在，這讓我們在優化時更加謹慎，不只是簡單地刪減或修改，而是深入思考每個功能的必要性，確保新系統既能提升效率，也不影響使用者習慣。這樣的過程充滿挑戰，也讓我們體會到持續迭代與驗證的重要性。

反覆修正的過程中，團隊間的溝通與協作成為關鍵，透過不斷交流，我們能夠發掘更多潛在問題，並在討論中激發出更完善的解決方案。這次的開發經驗不僅提升對系統架構的理解，也深刻體會到規劃與統整的重要性。未來，我們會持續優化模組設計，並根據使用者的回饋進行改進，讓後台系統能夠更貼近實際需求，為公司的專案發展提供更強而有力的支援。
